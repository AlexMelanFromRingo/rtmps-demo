# Журнал изменений

Все заметные изменения проекта записываются в этот файл.

Формат — [Keep a Changelog 1.1.0](https://keepachangelog.com/ru/1.1.0/), версии —

## [Unreleased]

### Добавлено
- Функции уровня Twitch / YouTube / Streamlabs (без чата):
  - подписки на каналы, счётчик подписчиков, лента «Отслеживаемые»;
  - записи эфиров (VOD) с перемоткой: пишутся из тех же сегментов без доп. кодирования,
    переживают failover, хранятся `VOD_RETENTION_DAYS`, счётчик просмотров, удаление владельцем;
  - мультистрим на Twitch / YouTube / Kick / любой RTMP(S)/SRT: копия видео, если платформа
    принимает кодек, статус по каждому направлению, ключи зашифрованы, защита от SSRF;
  - оверлей для OBS «Браузер»: оповещения о подписчиках и счётчик зрителей по секретной ссылке;
  - Enhanced Broadcasting: несколько видеодорожек от OBS отдаются без перекодирования;
  - режим низкой задержки (сегменты 1 с), графики здоровья эфира;
  - каталог категорий и поиск (pg_trgm);
  - профиль канала: аватар, описание, ссылки, отметка 18+;
  - 2FA (TOTP, RFC 6238) с резервными кодами, список сессий и выход на других устройствах,
    смена пароля.
- GitHub Actions:
  - `ci.yml` — typecheck и unit-тесты сервера, сборка web, `gofmt`/`go vet`/`go test` для srt-gateway,
    проверка конфигов наблюдаемости (`promtool`), сборка всех Docker-образов без публикации;
  - `e2e.yml` — полный e2e-набор в Docker по запросу и при пуше в ветку по умолчанию.
- Dependabot для npm (server, web), Go-модулей, Dockerfile, compose-файлов и GitHub Actions:
  раз в неделю, minor/patch собираются в группы.
- Необязательный стек наблюдаемости `docker-compose.observability.yml`:
  - Prometheus находит все реплики через Docker DNS, алерты покрыты unit-тестами `promtool`;
  - Grafana с дашбордом «StreamHub overview»;
  - описание в `docs/OBSERVABILITY.md`.
- Стандартные файлы репозитория: `LICENSE` (MIT), `SECURITY.md`, `CONTRIBUTING.md`,
  `CODE_OF_CONDUCT.md`, `.editorconfig`, `.gitattributes`.

## [2.0.0] — 2026-11-03

Полная переработка: из однопроцессного сервера на node-media-server проект стал
масштабируемой мультиарендной платформой (мини-Twitch).

### Добавлено
- Ingest на MediaMTX:
  - RTMP и Enhanced RTMP (H.264/HEVC/AV1/VP9);
  - SRT, мультиплексированный по `streamid` (один порт на всех);
  - WebRTC/WHIP;
  - авторизация публикаций через control plane, хуки жизненного цикла и heartbeat-регистрация узлов.
- Универсальный SRT-вход `srt-gateway` (Go, порт 8891): AV1/VP9/VP8/HEVC/H.264 в Matroska/WebM/FLV/MPEG-TS
  без перекодирования, опциональная парольная фраза.
- Stateless API на Fastify (N реплик):
  - аккаунты, каналы, ключи трансляции, каталог эфиров;
  - SSE через Valkey pub/sub, присутствие зрителей;
  - rate limit, защита от CSRF.
- Control loop с лидером по advisory lock Postgres:
  - уровневая сверка с ingest-узлами;
  - 30-секундное окно переподключения стримера;
  - самовосстановление заданий, подсчёт зрителей, удаление старых объектов.
- Воркеры на FFmpeg 9 (N реплик):
  - очередь заданий в Postgres (`SKIP LOCKED` + аренда), fencing, возврат «осиротевших» заданий;
  - исходник без перекодирования для H.264/HEVC/AV1 и H.264-лестница без апскейла;
  - fMP4 HLS в S3 с соблюдением порядка, собственный master-плейлист с `CODECS` по RFC 6381;
  - превью, degraded-режим при нехватке мощностей, перепланирование лестницы при росте разрешения источника.
- Edge на nginx: SPA, балансировка API с повторами, micro-cache HLS.
- Хранилища: PostgreSQL 18, Valkey 9, SeaweedFS (S3).
- Web: SPA на React 19 + hls.js — каталог, плеер с выбором качества и кодека, студия, эфир из браузера (WHIP).
- Метрики Prometheus у API (`:3000/metrics`), воркеров (`:9100/metrics`), MediaMTX (`:9998/metrics`)
  и srt-gateway (`:9101/metrics`).
- Документация: архитектура, контракт API, эксплуатация и runbook.
- Тесты: unit и e2e с реальными RTMP/SRT/WHIP-потоками в нескольких кодеках одновременно,
  проверками безопасности и перехватом транскода после `SIGKILL` воркера.
- `RESTART_POLICY` в compose (по умолчанию `no`: контейнеры не стартуют сами после перезагрузки).

### Изменено
- Внутренний секрет передаётся в заголовке `Authorization`, а не в query string.
- API доверяет ровно `TRUST_PROXY_HOPS` прокси, а не любому `X-Forwarded-For`.
- Эфир привязан к ingest-пути: сброс ключа во время эфира больше его не завершает (миграция 0002).
- Если кодек нельзя прочитать по выбранному протоколу (например, AV1 в MPEG-TS по SRT 8890),
  Студия показывает понятную ошибку, а не «эфир без видео».

### Исправлено
- Токен аренды на каждый захват задания (`lease_id`): после сбоя БД воркер не выполняет одно
  задание дважды, все записи задания проверяются по токену.
- Fencing срабатывает до истечения аренды, в том числе на зависших запросах.
- Остановка транскода (failover, деплой, перепланирование) больше не пишет `EXT-X-ENDLIST`
  в живой плейлист.
- Сверка не «перехватывает» источник туда-обратно, пока его видит хотя бы один узел.
- Таймауты и TCP keepalive для Postgres и S3, watchdog и ограниченная очередь выгрузки в воркере,
  повтор неудачных выгрузок сегментов.
- Гонки: переподключение на границе окна ожидания, `SSE add()`, утечка слушателя в `sleep()`,
  двойной reconnect `LISTEN`.
- MediaMTX сообщает 0x0 до первого SPS — такое разрешение больше не сохраняется.

### Безопасность
- Секреты и ключи трансляции вырезаются из логов и сохраняемых ошибок.
- Публичные ключи трансляции старой версии заменены ключами, которые проверяет control plane.

## [1.0.0] — 2025-11-29

Первая версия: однопроцессный RTMP-сервер. Исправления от 2026-06-14 вошли без смены номера
версии и перечислены ниже.

### Добавлено
- RTMP-сервер на node-media-server, конвертация в HLS через FFmpeg, веб-интерфейс на Express
  с управлением ключами трансляции и плеером Video.js.
- SRT-вход для любых кодеков (отдельный порт и процесс FFmpeg на каждый ключ).
- ABR 480p/720p/1080p, автоопределение NVENC, хранение ключей в SQLite, метрики через WebSocket.
- Инструкции для Windows/WSL2 и руководство по проблемам с кодеками.

### Исправлено (2026-06-14)
- Единый вывод HLS (master + именованные варианты) для RTMP и SRT.
- Корректная ABR-команда ffmpeg и имена каталогов вариантов.
- SRT-слушатели перезапускаются после окончания сессии.
- Определение аппаратного кодировщика пробным запуском.
- Конфигурация через переменные окружения, корректное завершение по SIGINT/SIGTERM, валидация ввода.
- Удалена зависимость `uuid` (уязвимость средней степени) в пользу `crypto.randomUUID()`.
